# Формат проекта HErPlan, версия 1

Статус: черновик v1 (задача Ф0-06). Поля добавляются по мере появления функций; удаление или переименование поля требует новой версии формата и миграции (`FR-SAV-07`).

Решения, на которых основан формат: [ADR-004](../adr/004-project-format.md) (раскладка «гибрид», атомарная запись, синтаксис вставок).

## Принципы

1. **Проект — обычная папка.** Её можно скопировать, положить в git, открыть в Obsidian или текстовом редакторе.
2. **Файлы — обычный JSON и Markdown**, без служебных заголовков. Все записи атомарные (временный файл → `fsync` → переименование).
3. **Ссылки только по ID.** Имена и пути можно менять, ссылки от этого не ломаются.
4. **Правки снаружи допустимы.** Если файл изменили в другой программе, HErPlan принимает изменения. Испорченным считается только JSON, который не разбирается, или пустой файл; тогда HErPlan предлагает копию из `backups/`.
5. **Кеш можно удалить.** Всё в `.herplan/` перестраивается из данных.

## Раскладка папки

```
<Проект>/                        имя папки свободное
  project.json                   паспорт проекта (обязателен)
  data/
    types.json                   типы сущностей и наборы свойств
    documents.json               папки и свои шаблоны документов (с 0.4)
    variables.json               реестр переменных и меток
    entities/<id>.json           одна сущность — один файл
    graphs/<id>.json             один граф (карта проекта, глава, дерево) — один файл со всеми узлами и связями
    boards/<id>.json             одна доска задач — один файл
  documents/<путь>/<имя>.md      документы; вложенные папки — папки пользователя
  assets/<путь>/<файл>           картинки и прочие файлы как есть; вложенные папки — папки пользователя
  backups/                       копии (см. ниже)
  .herplan/                      кеш и индексы; можно удалить
```

## Общие правила JSON

- UTF-8 без BOM, переводы строк LF, отступ 2 пробела, в конце файла перевод строки.
- Порядок ключей стабильный (как в этом документе), чтобы правка одного поля давала одну строку в diff.
- Даты — ISO 8601 в UTC: `"2026-10-18T09:30:00Z"`.
- ID — 16 символов Crockford base32 в нижнем регистре: `"k3v9q0d2m7x1c8bz"` (`app/src/core/ids.ts`).
- Ссылка на объект: `{ "kind": "entity", "id": "…" }`. Виды: `entity`, `type`, `graph`, `node`, `edge`, `document`, `board`, `task`, `asset`, `variable`.
- Неизвестные поля HErPlan сохраняет без изменений (совместимость с будущими версиями).

## `project.json`

```json
{
  "format": "herplan-project",
  "formatVersion": 1,
  "id": "k3v9q0d2m7x1c8bz",
  "name": "Мельница",
  "description": "",
  "cover": "assets/cover.png",
  "createdAt": "2026-10-18T09:30:00Z",
  "updatedAt": "2026-10-18T09:31:12Z",
  "createdWith": "0.1.0",
  "settings": {
    "backups": { "keep": 50, "intervalMinutes": 10 },
    "dialogueLimits": { "maxLines": 100, "maxLineChars": 100 }
  }
}
```

- `cover` — путь внутри проекта или `null`.
- `backups.keep` — число (хранить последние N) или `"all"`.

## `data/entities/<id>.json`

```json
{
  "id": "m1r4a0000000000a",
  "type": "character",
  "name": "Мира",
  "description": "Травница",
  "image": "assets/world/mira.png",
  "order": 10,
  "values": { "f-trust0000000001": 3, "f-lore00000000001": "Живёт у мельницы…" },
  "relations": [
    { "id": "r00000000000001x", "to": { "kind": "entity", "id": "b0r1s00000000000" }, "label": "наставница", "inverseLabel": "ученик", "description": "" }
  ]
}
```

- `type` — ID типа: встроенные `character`, `location`, `item` или свой тип из `data/types.json`.
- `image` — путь к картинке внутри проекта (`assets/…`) или `null`; `order` — ручной порядок (сортировка «вручную» в базе данных).
- `values` — значения по ID поля (поля описаны в типе и его наборах свойств), поэтому переименование и перенос поля не трогают файлы сущностей. Значение поля, удалённого из схемы, остаётся в файле.
  Значения по видам полей: `text`, `richtext` — строка; `number` — число или `null`; `percent` — число 0…100 или `null`; `bool` — `true`/`false`; `enum` — один из вариантов поля или `null`; `ref` — ID сущности или `null`; `refList` — массив ID; `tags` (с 0.4) — массив ID тегов справочника; `image` — путь `assets/…` или `null`; `color` — `"#rrggbb"` или `null`; `table` — `{ "rows": [["ячейка", …], …] }` по столбцам поля.
- `relations` — связи хранятся у одной стороны; вторая сторона видит их через индекс. У каждой стороны своя подпись: `label` — как эта сущность называет другую («жена»), `inverseLabel` — как другая называет эту («муж»). При удалении сущности связи, указывающие на неё, удаляются.
- Файлы версии 0.2 (`{ "id", "type", "name", "description", "image", "order" }`) читаются без изменений: `values` и `relations` считаются пустыми.
- С 0.5 карточка может отличаться от своего типа (все три ключа необязательны; нет ключа — как у типа):
  - `fields` — поля только этой карточки, в том же виде, что поля типа (`{ "id", "label", "type", … }`, см. `data/types.json`); их значения — в `values`, как у остальных полей.
  - `hiddenFields` — ID полей типа (и его наборов свойств), которых у этой карточки нет. Значения скрытых полей остаются в `values` и возвращаются, когда поле снова показано.
  - `card` — блоки, которые эта карточка показывает или скрывает вопреки типу, в том же виде, что `card` у типа.

```json
{
  "id": "m1r4a0000000000a",
  "type": "character",
  "name": "Мира",
  "fields": [{ "id": "f-nick0000000001", "label": "Прозвище", "type": "text" }],
  "hiddenFields": ["f-hp000000000001"],
  "card": { "relations": false },
  "values": { "f-nick0000000001": "Травка", "f-hp000000000001": 120 }
}
```

## `data/types.json`

```json
{
  "types": [
    { "id": "character", "name": "", "parent": null, "icon": null, "color": null, "propertySets": ["ps-combat0000000a"], "fields": [
      { "id": "f-trust0000000001", "label": "Доверие", "type": "number" }
    ] },
    { "id": "t-knight00000000a", "name": "Рыцарь", "parent": "character", "icon": null, "color": null, "propertySets": [], "fields": [] }
  ],
  "propertySets": [
    { "id": "ps-combat0000000a", "name": "Бой", "fields": [
      { "id": "f-health000000001", "label": "Здоровье", "type": "number" },
      { "id": "f-class0000000001", "label": "Класс", "type": "enum", "options": ["воин", "маг"] }
    ] }
  ],
  "relationLabels": [ { "label": "сюзерен", "inverse": "вассал" } ],
  "catalogs": [
    { "id": "c-traits00000000a", "name": "Черты", "tags": [
      { "id": "tg-agile0000000a", "name": "ловкий", "description": "уклоняется от первой атаки", "color": null }
    ] }
  ]
}
```

- Встроенные типы `character`, `location`, `item` есть всегда (если их нет в файле, HErPlan считает их пустыми); у них пустое `name` — интерфейс показывает название на своём языке. Их можно дополнять полями и наборами, но не удалять.
- `parent` — подтип наследует поля и наборы свойств всех типов выше. Порядок полей у сущности: сначала поля верхнего типа (сначала его наборов, потом свои), затем каждого подтипа ниже.
- Виды полей: `text`, `richtext` (длинный текст), `number`, `percent`, `bool`, `enum` (`options`), `ref` и `refList` (`target` — ID типа или `null`, любая сущность), `image`, `color`, `table` (`columns`).
- Набор свойств подключается к типам через `propertySets`; поле, добавленное в набор, появляется у всех типов с этим набором.
- При удалении своего типа его подтипы и сущности переходят к типу выше (верхнего уровня — в `item`).
- `relationLabels` — пары подписей связей, которые проект запомнил; HErPlan дополняет их встроенными парами на языке интерфейса.
- `catalogs` (с 0.4) — справочники тегов (черты, способности, пассивки): у тега `id`, `name`, `description`, `color` (`"#rrggbb"` или `null`). Поле вида `tags` берёт теги из справочника `catalog` (ID или `null`, пока не выбран); значение поля — массив ID тегов. ID тегов уникальны во всём проекте. Удаление тега снимает его со всех сущностей; у удалённого справочника поля получают `catalog: null`, значения остаются.
- `card` у типа (с 0.4, необязательно) — какие блоки показывает карточка: `{ "picture", "description", "relations", "variables", "uses" }`, каждый `true` или `false`. Не указан — как у типа выше; у верхнего типа — показан. Скрытие ничего не удаляет из файлов.

## `data/variables.json`

```json
{
  "variables": [
    { "id": "v-spared00000001", "name": "пощадил_рыцаря", "type": "bool", "initial": false, "scope": "project", "owner": null, "description": "" },
    { "id": "v-miratrust00001", "name": "доверие", "type": "int", "initial": 0, "scope": "project", "owner": { "kind": "entity", "id": "m1r4a0000000000a" }, "description": "" },
    { "id": "v-mood0000000001", "name": "настроение", "type": "enum", "values": ["спокойна", "рада"], "initial": "спокойна", "scope": { "kind": "graph", "id": "g-chapter1000001" }, "owner": null, "description": "" }
  ],
  "labels": [
    { "id": "l-combat00000001", "name": "Бой", "color": "#c2611a", "pattern": "stripes" }
  ]
}
```

- `type`: `bool`, `int`, `float`, `string`, `enum` (список `values`), `entity` (карточка мира; значение — ID карточки или `null`). Старое значение `"number"` читается как `float`.
- `scope`: `"project"` или `{ "kind": "graph", "id": "<глава>" }` — переменная главы видна в ней и во вложенных главах и сбрасывается к начальному значению при входе в главу.
- Имя — буквы (латиница, кириллица), цифры и `_`, не с цифры и не слово языка выражений. Имена уникальны там, где переменные видны вместе.
- В выражениях переменная сущности пишется как `Мира.доверие` (ADR-005); пробелы и знаки в имени карточки заменяются на `_`. При переименовании переменной или карточки HErPlan переписывает все выражения проекта.
- `labels` — метки проекта (название и цвет); задачи начнут ими пользоваться в версии 0.6.

## `data/graphs/<id>.json`

```json
{
  "id": "g-chapter1000001",
  "kind": "chapter",
  "name": "Глава 1. Мельница",
  "parent": { "kind": "node", "id": "n-ch1onstory0001" },
  "nodes": [
    { "id": "n-start000000001", "kind": "start", "title": "Начало", "x": 0, "y": 0, "w": 180, "h": 80 },
    { "id": "n-dialog0000001", "kind": "dialogue", "title": "У мельницы", "x": 260, "y": 0, "w": 240, "h": 140,
      "lines": [ { "id": "dl000000000001", "speaker": { "kind": "entity", "id": "m1r4a0000000000a" }, "text": "Ты пришёл." } ] },
    { "id": "n-choice0000001", "kind": "choice", "title": "Как ответить?", "x": 560, "y": 0, "w": 240, "h": 140,
      "options": [ { "id": "o00000000000001", "text": "Пощадить рыцаря", "condition": "", "effects": "пощадил_рыцаря = истина" } ] }
  ],
  "edges": [
    { "id": "e00000000000001", "from": { "node": "n-start000000001", "port": "out" }, "to": { "node": "n-dialog0000001", "port": "in" }, "condition": "" }
  ],
  "groups": []
}
```

- `kind` графа: `projectMap`, `story` (обзор глав), `chapter`, `tree`, `freeform`.
- Карта проекта (с 0.4) — граф `kind: "projectMap"`, один на проект. Кроме обычных узлов, заметок, рамок и стрелок на ней есть узлы `kind: "ref"` с полем `ref: { "kind": "chapter" | "document" | "entity" | "asset", "id" }` — карточка объекта проекта (ID главы, документа, сущности или путь `assets/…`). Что показывает карточка, берётся из самого объекта; заголовок узла — только подпись вида объекта.
- Условия и эффекты хранятся исходным текстом (ADR-005); дерево разбора строится при загрузке и при экспорте.

### Узлы сценария (с версии 0.2)

Общие поля узла: `id`, `kind`, `title`, `x`, `y`, `w`, `h`, необязательные `text`, `color`, `icon`, `comment` и `plotRole` (`"consequence"` — последствие эффекта бабочки, `"payoff"` — «выстрел» ружья; нужны проверкам). С 0.3.1 узел может быть и тем и другим сразу: тогда пишется `plotRoles` — список ролей; если он есть, `plotRole` не читается. Файлы с одним `plotRole` читаются как раньше.

| `kind` | свои поля |
| --- | --- |
| `start`, `scene`, `end`, `node` | — |
| `dialogue` | `lines: [{ id, speaker, text }]` (`speaker` — ID карточки или `null`), `expanded` — все реплики на холсте |
| `choice` | `text` — вопрос; `options: [{ id, text, condition, effects, note? }]`; `note` — комментарий к варианту (с 0.3) |
| `condition` | `expr` — условие; выходы `yes` и `no` |
| `effect` | `effects` |
| `butterfly` | `effects`, `links: [{ graph, node }]` — последствия (с 0.3 не создаётся, но открывается) |
| `gun` | `links: [{ graph, node }]` — где «выстрелит» (с 0.3 не создаётся, но открывается) |
| `jump` | `target: { graph, node }` или `null` |
| `chapter` | `graph` — ID графа главы, `image` — путь к картинке или `null` |
| `character`, `location`, `item` | `ref` — ID карточки мира или `null` |
| `sticker` | заметка: только `text` |

### Литературные приёмы поверх узлов (с версии 0.3)

Чеховское ружьё и эффект бабочки — не отдельные узлы, а метки в необязательном поле узла `marks`:

```json
"marks": [
  { "id": "m-rifle", "device": "gun",
    "anchor": { "kind": "line", "id": "l2" },
    "range": { "start": 17, "end": 29, "quote": "старое ружьё" },
    "links": [ { "graph": "g-ch3", "node": "c-shot" } ],
    "note": "Выстрелит в тронном зале", "variables": [] }
]
```

- `device` — `"gun"` или `"butterfly"`; позже могут появиться другие приёмы.
- `anchor` — на чём метка: `{ "kind": "node" }` (сам узел и его `text`), `{ "kind": "option", "id" }` или `{ "kind": "line", "id" }`. Метка удаляется вместе со своим вариантом или репликой.
- `range` — выделенный фрагмент текста этого места: смещения в UTF-16 и сам фрагмент (`quote`); `null` — всё место целиком. Если текст изменили вне HErPlan и смещения больше не указывают на `quote`, фрагмент ищется заново по `quote` (ближайшее вхождение), а если его нет — метка относится ко всему месту.
- `links` — где ружьё выстрелит / где последствия бабочки; `note` — заметка; `variables` — ID затронутых переменных (только для бабочки, необязательно).

### Переменные в тексте (с версии 0.3)

В описании узла (`text`), комментарии узла (`comment`) и комментарии варианта (`note`) можно менять переменные: `{деньги += 10}` или без скобок `деньги += 10` (без скобок — только если `деньги` — переменная, видимая из этого графа, и справа одно значение). В репликах — только в фигурных скобках. `{деньги}` (имя без оператора) при прохождении показывает значение. Прохождение применяет эффекты описания, комментария и реплик, когда узел показан, а эффекты комментария варианта — когда вариант выбран. Файл хранит текст как написан.

Граф главы (`kind: "chapter"`) хранит в `parent` узел-главу: `{ "kind": "node", "id": "<узел>" }`. Удаление узла-главы удаляет и её граф (с вложенными главами), копирование — копирует граф с новыми ID; отмена возвращает всё одним шагом.

### Порты и связи

У большинства узлов четыре точки подключения на сторонах: `in` (слева), `out` (справа), `top`, `bottom`. Тянуть связь можно от любой; направление связи — от узла, откуда её потянули. Узел `start` только отдаёт связи, `end` и `jump` только принимают. У выбора каждый вариант — свой выход справа (`port` = ID варианта), у условия — выходы `yes` и `no`. Связь хранит `from` и `to` как `{ node, port }`, необязательные `label`, `color` и `condition` (условие перехода).

## Документы `documents/**/*.md` (с 0.4)

Обычный Markdown (GFM: таблицы, зачёркивание) и вставки HErPlan:

- `[[ent:<id>|Подпись]]` — ссылка на карточку; `[[doc:<id>|Название]]` — на документ; `[[node:<граф>/<узел>|Название]]` — на узел сценария; с 0.5 `[[asset:<путь>|имя файла]]` — на файл ресурсов (`assets/…`). Подпись хранится для читаемости вне HErPlan и обновляется при сохранении.
- С 0.5 у ссылки может быть третья часть — куда ведёт щелчок, если объект есть в нескольких местах: `[[ent:<id>|Мира|map:<узел карты>]]`. Места: `card:<id>` (карточка в базе), `doc:<id>` (документ), `story:<граф>/<узел>` (узел на холсте сценария), `map:<узел>` (узел карты проекта), `assets:<путь>` (файл в ресурсах). Без третьей части, или когда этого места уже нет, щелчок открывает объект там, где он хранится: карточку в базе, документ, узел, файл в ресурсах.
- `{{ent:<id>.<поле>}}` — живое значение поля карточки: `name`, `description` или ID поля.
- Подчёркивание пишется тегом `<u>…</u>`, цвет и шрифт — `<font color="red" face="serif">…</font>` (цвета: `red`, `orange`, `green`, `blue`, `violet`, `grey`; шрифты: `serif`, `monospace`). Пустой абзац — строкой `&#160;`.
- Если обычная запись форматирования неоднозначна (её нельзя прочитать обратно тем же текстом), абзац пишется с тегами `<strong>`, `<em>`, `<s>`, `<u>`, `<code>`, `<a href>`, вставки — как `<span data-link="ent:<id>">Подпись</span>` (место ссылки — атрибутом `data-place`) и `<span data-field="<id>.<поле>"></span>`, а знаки разметки в тексте — числовыми сущностями (`&#42;`). HErPlan проверяет каждое сохранение: записанное читается обратно и сравнивается с документом (ADR-003, задача Ф5-10).
- Нормализации, которые делает Markdown и которые HErPlan не считает потерей: пробелы в начале и конце строки; первая строка таблицы — всегда заголовочная; в ячейке таблицы — одна строка текста; два нумерованных списка подряд читаются как один; пустая строка внутри пункта списка или цитаты рядом с другими блоками; несколько пробелов подряд в ячейке таблицы — один пробел; жирный, курсив и код на пробелах и на вставках.

Блок метаданных в начале файла (YAML front matter) хранит ID документа; остальные строки блока HErPlan сохраняет как были:

```markdown
---
herplan-id: d-gdd00000000001
tags: [мир]
---
# Диздок
```

Файл без `herplan-id` (например, созданный в Obsidian) получает ID `path:<путь>`; HErPlan добавит блок, когда сохранит документ.

- Документ в корзине лежит в `documents/.trash/<id>.md` (папки с точкой Obsidian не показывает) с полями `herplan-trashed-from` (откуда удалён) и `herplan-trashed-at`. Восстановление возвращает его в прежнюю папку.
- `data/documents.json` — `{ "folders": ["Мир", "Мир/Локации"], "templates": [{ "id", "name", "body" }] }`: папки, которые нужно показывать и пустыми, и свои шаблоны документов (Markdown). Файла может не быть.
- С 0.5 файлы, перетащенные в документ из проводника или вставленные из буфера обмена, копируются в ресурсы, в папку `assets/Вложения в документы/` (в английском интерфейсе — `assets/Document attachments/`; если одна из них уже есть, используется она). Картинки встают в текст картинками, остальные файлы — ссылками `[[asset:…]]`. Переименование и перенос файла в ресурсах меняют пути в картинках, ссылках `[[asset:…]]` и местах `assets:…`.

## Резервные копии `backups/`

```
backups/
  auto/2026-10-18T09-40-00Z.zip      автоматические копии; хранятся по правилу settings.backups.keep
  manual/2026-10-18T10-00-00Z.zip    ручные версии; хранятся всегда
  manual/2026-10-18T10-00-00Z.json   подпись ручной версии
```

Копия — zip-архив всего проекта, кроме `backups/` и `.herplan/`. Копия делается раз в `intervalMinutes` минут работы, если были изменения, при закрытии проекта и перед миграцией формата (`FR-SAV-04`).

## Кеш `.herplan/`

| файл | что хранит |
| --- | --- |
| `.herplan/workspace.json` | открытые вкладки и активная вкладка: `{ "tabs": [{ "id": "…", "kind": "story" }], "active": "home" }` |

Если файл повреждён или удалён, проект открывается с одной вкладкой «Дом».

## Настройки программы (вне проекта)

Язык, акцент, масштаб интерфейса, интервал автосохранения и список недавних проектов хранятся не в проекте, а в `settings.json` в папке пользователя (`%APPDATA%\io.github.herput0c.herplan\`). Деинсталлятор не трогает проекты; повторная установка сохраняет настройки. Повреждённый `settings.json` переименовывается в `settings.damaged-<время>.json`, и программа запускается с настройками по умолчанию.

## Версии формата и миграции

- `formatVersion` растёт, только если старая версия HErPlan не сможет корректно прочитать проект.
- Перед миграцией делается ручная версия с подписью «перед обновлением формата до vN».
- Проект более новой версии, чем знает приложение, открывается только для чтения с предупреждением.
