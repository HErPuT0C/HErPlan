# ADR-003. Редактор текста

Статус: **принято** (2026-10-18) с обязательной доработкой сохранения Markdown (см. «Последствия»)
Дата: 2026-10-18
Задача плана: Ф0-05

## Контекст

Документы хранятся в Markdown со своими вставками (`FR-DOC-01`). Требования к поведению текста (`FR-DOC-02`): отмена без «возвратов», вставка из Word и браузера без поломки ввода, контекстное меню, русский ввод и проверка орфографии. Вставки из базы данных должны обновляться сами (`FR-DOC-03`). Это самый рискованный компонент (TR1 в `docs/spec.md`).

## Варианты

1. **TipTap 3** (ProseMirror, MIT) с официальным расширением `@tiptap/markdown`.
2. Milkdown (ProseMirror, Markdown-ориентированный, MIT).
3. CodeMirror 6 с живым предпросмотром (как исходный режим Obsidian).
4. Lexical (Meta, MIT).

Прототипировался только вариант 1: самая большая экосистема (таблицы, изображения, вставка из Word), зрелая модель отмены ProseMirror, официальная поддержка Markdown с собственными токенами. К остальным вернёмся, только если TipTap не пройдёт проверки.

Прототип: `prototypes/web/src/editor/`. Синтаксис вставок-кандидат: `[[ent:mira|Мира]]` (ссылка; подпись после `|` делает файл читаемым в Obsidian) и `{{ent:mira.доверие}}` (живое поле). Окончательный синтаксис — ADR-004.

## Замеры и проверки

Автоматически (headless Chromium, CI):
- Markdown → редактор → Markdown даёт тот же текст ✅.
- **Найден и исправлен дефект библиотеки:** `@tiptap/markdown` 3.32 применяет жирный, курсив и зачёркивание только к обычному тексту. Поэтому `**[[ent:mira|Мира]]**` терял жирный при открытии файла, то есть менялся текст пользователя. Исправление — 30 строк: `markdown-marks.ts` дополняет разбор, вставки сами оборачивают себя при сохранении. Автопроверка в прототипе ловит регрессию. Это нужно сообщить разработчикам TipTap.
- Живые вставки обновляются сразу при изменении данных ✅.

Вручную на Windows (владелец, ноутбук из ADR-001, обе оболочки): **9 из 9** — вставка из Word и браузера, ввод после Ctrl+V, отмена и повтор без «возвратов», контекстное меню, русский ввод и орфография, «@» для вставки сущности, мгновенная подсветка кнопок панели.

Владелец один раз увидел, что автопроверка Markdown провалилась после каких-то правок, и не смог повторить. Чтобы найти причину, написан **фаззер** `prototypes/web/scripts/fuzz-markdown.mjs`: 40 серий по 60 случайных правок (текст со спецсимволами, форматирование произвольных диапазонов, списки, цитаты, таблицы, вставки), после каждой правки — проверка «Markdown → новый редактор → Markdown» и сравнение документа. Найденные классы:

| класс | пример | оценка |
| --- | --- | --- |
| **A. Форматирование на границе слова или знака** | `Ме*льница: …—*` после перечитывания превращается в буквальные `\*`, жирный пропадает | **потеря данных**; скорее всего, это и видел владелец |
| B. Первая строка таблицы | обычные ячейки становятся заголовочными | нормализация: в Markdown у таблицы всегда есть строка заголовков |
| C. Несколько абзацев или цитата в ячейке таблицы | превращаются в переносы строк или текст с `&gt;` | редактор не должен позволять блоки внутри ячейки |
| D. Пробелы в начале и конце абзаца, табуляция | обрезаются или заменяются пробелами | безвредная нормализация, документируется |
| E. Обычный текст, похожий на наш синтаксис | буквальный `[[ent:boris|…]]` становится вставкой | редко; лечится экранированием `[[` и `{{` в тексте |
| F. Адрес сайта в тексте | становится ссылкой | мелочь; ссылку лучше создавать сразу при вводе |
| G. Подчёркивание | сохраняется как `++текст++` (не стандарт, Obsidian не понимает) | писать `<u>…</u>` |

Проверено, что парсер читает HTML-теги `<em>`, `<strong>`, `<s>`, `<u>` обратно как форматирование, а наши вставки — как HTML-элементы `<span data-entity-link>`. Значит, класс A лечится без смены редактора.

## Решение

**TipTap 3 + `@tiptap/markdown`** с нашим расширением для вставок и **самопроверяющим сохранением**.

## Последствия

- **Самопроверяющее сохранение** (задача Ф5-10): после сохранения каждый абзац перечитывается; если документ изменился, форматирование этого абзаца записывается HTML-тегами (`<strong>`, `<em>`, `<s>`, `<u>`, вставки — `<span data-entity-…>`). Markdown остаётся читаемым, данные не теряются.
- Схема редактора запрещает то, чего не умеет Markdown: блоки внутри ячеек таблицы, таблицу без строки заголовков (классы B и C). Текст, похожий на наш синтаксис, экранируется (класс E).
- Фаззер работает в CI. Критерий приёмки Ф5: **ноль** расхождений классов A, C, E; нормализации B, D, F документированы в справке.
- Обновления `@tiptap/markdown` проверяются автотестами на сохранение форматирования вокруг вставок.
- Постраничная разметка в редакторе не нужна: документ — поток, страницы появляются только в PDF (ADR-006).

## Итог реализации (0.4, задачи Ф5-10, Ф5-11)

Самопроверяющее сохранение сделано в `app/src/documents/markdown.ts`, фаззер — `app/src/documents/markdown.fuzz.test.ts`, обязательный шаг CI (`npm run test:fuzz`, 40 серий по 60 правок, около 5 минут). Что понадобилось сверх плана:

- текст внутри HTML-тегов читается как HTML, а не как Markdown: знаки разметки и `<`, `&` в безопасной форме пишутся числовыми сущностями; HTML читается с сохранением пробелов (`preserveWhitespace: 'full'`), иначе `<u> </u>` терял пробел;
- соседние куски с одинаковым оформлением пишутся внутри одной пары тегов;
- пустой абзац пишется `&#160;`, пустой заголовок — `##`: иначе они пропадали и следующие блоки сдвигались;
- два списка подряд разделяются сменой маркера; для нумерованных списков читатель TipTap 3.32 смену `1.` на `1)` не различает — это записано как нормализация;
- исправление для жирного вокруг вставок (`applyMarkToContent`) по-прежнему нужно в 3.32.

Итог фаззера на момент приёмки Ф5-10: ноль расхождений; нормализации перечислены в `docs/format/project-v1.md`.
