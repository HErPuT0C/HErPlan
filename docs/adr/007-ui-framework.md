# ADR-007. Фреймворк интерфейса и структура кода

Статус: принято (2026-10-18; владелец утвердил переход к Ф1)
Дата: 2026-10-18
Задача плана: Ф1-01

## Контекст

Оболочка — Tauri 2 (ADR-001): интерфейс в WebView2, файловая логика на Rust. Редактор текста — TipTap 3 (ADR-003). Холст рисуется своим движком вне фреймворка (ADR-002). Нужен фреймворк для остального интерфейса: стартовый экран, дашборд, вкладки, настройки, карточки базы данных, канбан, панели свойств. Интерфейс должен оставаться отзывчивым на эталонном слабом ПК (ADR-001).

## Варианты

1. **React 19**: самая большая экосистема (у TipTap официальная обвязка `@tiptap/react`, готовые решения для перетаскивания и виртуальных списков), предсказуемая модель. Немного тяжелее альтернатив.
2. Solid или Svelte 5: легче и быстрее на мелких обновлениях, но меньше готовых компонентов, а TipTap для них поддерживается сообществом.
3. Без фреймворка: максимум скорости, но всё — от списков до модальных окон — пришлось бы писать и поддерживать самим.

## Решение

**React 19 + TypeScript + Vite.** Узкие места производительности (холст, длинные списки) живут вне React или виртуализируются, поэтому накладные расходы React на остальной интерфейс несущественны. Экосистема и обвязка TipTap экономят месяцы.

Правила:
- Состояние проекта живёт в доменном ядре с шиной команд и undo (Ф1-02), а не в React. Компоненты подписываются через `useSyncExternalStore`.
- Без тяжёлых библиотек компонентов: свои компоненты на CSS-переменных (Ф1-04) — проще соблюсти лёгкий визуальный стиль.
- Все строки интерфейса — через модуль локализации (Ф1-05), ни одной строки в разметке напрямую.

## Структура репозитория

```
app/                    приложение HErPlan
  src/                  интерфейс (TypeScript, React)
    core/               доменная модель, шина команд, undo — без React и без ввода-вывода
    ui/                 компоненты, экраны
    i18n/               строки RU и EN
  src-tauri/            оболочка и бэкенд на Rust
crates/
  herplan-storage/      атомарная запись, копии, раскладка проекта (из прототипа ADR-004)
prototypes/             прототипы фазы Ф0 (не продукт)
docs/                   спецификация, ADR
```

### Уточнение (Ф1, 2026-10-18)

```
app/src/
  core/        доменная модель, Store с undo, проект: загрузка, автосохранение, копии, миграции
  platform/    контракт с Rust-бэкендом (types.ts); Tauri-реализация и реализация в памяти для веб-сборки
  state/       состояние программы: настройки, открытый проект, вкладки
  ui/          компоненты (components/), экраны (start/, workspace/, settings/, project/), тема (theme/)
  i18n/        словари RU и EN
app/src-tauri/src/commands.rs   команды Tauri — тонкие обёртки над herplan-storage
```

Интерфейс обращается к диску только через `platform/`. В обычном браузере (сервер разработки, e2e-тесты Playwright) подставляется реализация в памяти, поэтому сквозные сценарии (создание, повторное открытие, история, настройки) проверяются в CI без Windows.

## Последствия

- Тесты: Vitest для `core` и компонентов, Playwright для сквозных сценариев в веб-сборке (работают в контейнере без Windows), `cargo test` для Rust. На Windows итог проверяет владелец по чек-листам вех.
- Проверка типов и линтер — в CI на каждый push.
