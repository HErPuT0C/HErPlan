# Архитектурные решения (ADR)

Каждое значимое техническое решение записывается отдельным файлом `NNN-краткое-название.md`. Решение не переписывается задним числом: если оно меняется, пишется новый ADR, а старый получает статус «заменено ADR-NNN».

| ADR | тема | статус |
| --- | --- | --- |
| [001](001-desktop-shell.md) | Оболочка Windows-приложения | **принято: Tauri 2** (Ф0-03) |
| [002](002-canvas-rendering.md) | Отрисовка холста | **принято: гибрид WebGL + DOM** (Ф0-04) |
| [003](003-text-editor.md) | Редактор текста | **принято: TipTap 3** + самопроверяющее сохранение (Ф0-05) |
| [004](004-project-format.md) | Формат папки проекта, запись на диск, вставки в Markdown | принято: атомарная запись и гибридная раскладка; синтаксис вставок — кандидат (Ф0-06, Ф0-07, Ф0-10) |
| [005](005-expression-language.md) | Язык выражений | принято: свой минимальный язык (Ф0-08) |
| [006](006-pdf.md) | Генерация PDF | принято: pdfmake (Ф0-09) |
| [007](007-ui-framework.md) | Фреймворк интерфейса и структура кода | принято: React 19 + TypeScript + Vite (Ф1-01) |

```markdown
Задача плана: Ф0-NN

## Контекст
Какую проблему решаем, какие требования из docs/spec.md затронуты.

## Варианты
Кандидаты и критерии сравнения.

## Замеры
Что измерили, на чём, с какими цифрами. Ссылки на прогоны CI.

## Решение
Что выбрали и почему.

## Последствия
Что это даёт, чем платим, что пересмотреть позже.
```
