# Архитектурные решения (ADR)

Каждое значимое техническое решение записывается отдельным файлом `NNN-краткое-название.md`. Решение не переписывается задним числом: если оно меняется, пишется новый ADR, а старый получает статус «заменено ADR-NNN».

| ADR | тема | статус |
| --- | --- | --- |
| 001 | Оболочка Windows-приложения | в работе, ждёт замеров CI и владельца (Ф0-03) |
| [002](002-canvas-rendering.md) | Отрисовка холста | предложено, ждёт замеров владельца (Ф0-04) |
| [003](003-text-editor.md) | Редактор текста | предложено: TipTap 3, ждёт проверок владельца (Ф0-05) |
| [004](004-project-format.md) | Формат папки проекта, запись на диск, вставки в Markdown | черновик: запись на диск проверена (Ф0-06, Ф0-07, Ф0-10) |
| [005](005-expression-language.md) | Язык выражений | предложено: свой минимальный язык (Ф0-08) |
| [006](006-pdf.md) | Генерация PDF | предложено: pdfmake (Ф0-09) |

## Шаблон

```markdown
# ADR-NNN. Название

Статус: предложено | принято | заменено ADR-NNN
Дата: ГГГГ-ММ-ДД
Задача плана: Ф0-NN

## Контекст
Какую проблему решаем, какие требования из docs/spec.md затронуты.

## Варианты
Кандидаты и критерии сравнения.

## Замеры
Что измерили, на чём, с какими цифрами. Ссылки на прогоны CI.

## Решение
Что выбрали и почему.

## Последствия
Что это даёт, чем платим, что пересмотреть позже.
```
