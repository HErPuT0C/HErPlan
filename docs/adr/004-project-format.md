# ADR-004. Формат папки проекта, запись на диск, вставки в Markdown

Статус: черновик (часть про запись на диск проверена прототипом; формат файлов — задача Ф0-06)
Дата: 2026-10-18
Задачи плана: Ф0-06, Ф0-07, Ф0-10

## Контекст

Проект — папка на диске (`docs/spec.md`, раздел 6): JSON для структурированных данных, Markdown для документов, обычные файлы для ассетов, копии рядом. Главное требование — ни одна авария не портит проект (`FR-SAV-03`, `NFR-06`).

## Запись на диск (Ф0-10, проверено)

Прототип `prototypes/storage`: файл пишется во временный рядом, сбрасывается на диск (`fsync`), затем атомарно заменяет старый через переименование. В первой строке хранится SHA-256 содержимого, поэтому порчу можно обнаружить при чтении.

Тест: писатель в отдельном процессе бесконечно перезаписывает файл на 1–2 МБ, его убивают в случайный момент (30–400 мс), затем файл проверяется. Контрольная группа пишет файл напрямую поверх старого, как незащищённое сохранение.

| ОС | способ | убийств | файл цел | испорчен |
| --- | --- | --- | --- | --- |
| Linux (контейнер) | атомарная замена | 200 | 200 | **0** |
| Linux (контейнер) | прямая перезапись (контроль) | 100 | 67 | **33** (пустой файл) |
| Windows (CI) | атомарная замена | 200 | заполняется по CI | |
| Windows (CI) | прямая перезапись (контроль) | 100 | заполняется по CI | |

Ограничение теста: убийство процесса — не то же самое, что отключение питания. От пропадания питания защищает `fsync` перед переименованием; в контейнере это не проверить, на практике это стандартная гарантия файловых систем NTFS и ext4.

Вывод для приложения:
- все записи проекта идут только через атомарную замену;
- при открытии проекта удаляются забытые временные файлы `.*.tmp-*`: прототип оставлял по одному на каждое убийство;
- контрольная сумма проверяется при чтении; при несовпадении предлагается копия из `backups/`.

## Формат файлов (Ф0-06, не начато)

Варианты: файл на объект или файл на модуль. Решение — по прототипу на 100 000 объектов: время открытия, размер diff при правке одной реплики.

## Вставки в Markdown (Ф0-07, кандидат)

Проверено в прототипе редактора (ADR-003):
- `[[ent:mira|Мира]]` — ссылка на сущность. Подпись после `|` показывается в Obsidian как текст ссылки, поэтому файл читаем и вне HErPlan.
- `{{ent:mira.доверие}}` — живое значение поля.
- Жирный, курсив и зачёркивание вокруг вставок сохраняются.
