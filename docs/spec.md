# HErPlan — спецификация v0

Дата: 2026-10-18. Это требования к первой версии HErPlan. Порядок работ — в [`PIPELINE.md`](../PIPELINE.md), архитектурные решения — в [`docs/adr/`](adr/).

Приоритеты: **MVP** — первая версия, **Желат.** — 1.x, **Позднее** — после 1.x.

## 1. Принципы

1. Данные пользователя неприкосновенны.
2. Один язык взаимодействия во всех редакторах.
3. Всё связано ссылками, а не копиями.
4. Открытый формат: папка проекта, которую можно прочитать без HErPlan.
5. Быстро на больших проектах и на слабых ПК; визуально просто: без размытий, свечений и тяжёлых анимаций.
6. Постепенное раскрытие функций.
7. Независимость: своё имя, стиль, тексты, шаблоны, пример проекта.

## 2. Модули HErPlan v1

1. **Холст** (общий движок) с типами графов: *карта проекта*, *сценарий* (главы → сцены), *дерево* (навыки, данные, отношения) как пресет, а не модуль.
2. **База данных:** персонажи, локации, предметы и любые свои типы; связи.
3. **Документы.**
4. **Задачи** (канбан).
5. **Ресурсы.**
6. **Оболочка:** стартовый экран, дашборд, поиск, история и копии, настройки.

Не входят в v1: уровни, настольные игры, порты, языки кроме RU и EN.

## 5. Пользовательские сценарии

```
US-01 Новый проект ≤ 3 действий: «Создать» -> имя (папка и обложка по умолчанию) -> дашборд
US-02 Персонаж: БД -> «Персонаж» -> перетащить портрет из проводника -> поля -> связь «Наставник» с Элдер Винном
      (у Винна автоматически появляется «Ученик»)
US-03 Предметы: тип «Оружие» наследует набор «Боевые параметры» -> 20 предметов -> добавить поле в набор ->
      поле появилось у всех 20
US-04 Сцена с выбором: глава -> диалог (30 реплик) -> выбор (3 варианта) -> вариант «Пощадить» ставит
      spared_knight = true -> в главе 4 условие spared_knight -> подсветка «где читается»
US-05 Проверить ветку: «Прохождение» с узла -> выборы -> панель переменных -> правка значения -> перезапуск
US-06 Карта проекта: перетащить главы, GDD и доску задач на карту -> двойной клик открывает
US-07 GDD: шаблон -> живые карточки персонажей и таблица предметов -> PDF
US-08 Задачи: «Связать с объектом» -> на карточке сущности видны её задачи
US-09 Сбой: питание пропало -> запуск -> проект открыт, потеряно ≤ 5 с; при повреждении предложен список копий
US-10 Отдать программисту: экспорт JSON -> импортёр Unity или GameMaker (после MVP)
US-11 Найти «серу» -> в выдаче «Sera» (имя) выше, чем документы, где «Sera» в тексте
```

## 6. Хранение и предварительная модель данных

**Почему не один JSON с изображениями.** Изображения внутри JSON пришлось бы кодировать (base64 увеличивает объём на треть). Тогда каждое автосохранение переписывает сотни мегабайт, весь проект держится в памяти, а повреждение одного файла губит всё.

**Решение: папка проекта (по образцу Obsidian).**

```
MyGame.herplan/            (папка проекта; имя папки свободное)
  project.json             метаданные, настройки проекта, версия формата
  data/                    структурированные данные (JSON)
    entities/…  graphs/…  boards/…  types/…  variables.json
  documents/               документы в Markdown со своими вставками
  assets/                  картинки и файлы как есть, с вложенными папками пользователя
  backups/                 копии по расписанию и ручные версии
  .herplan/                кеш и индекс поиска (можно удалить, перестраивается)
```

На этапе архитектуры остаётся один вопрос: один JSON на модуль или один файл на объект. Склоняюсь к файлу на объект: меньше перезаписей, удобно для git, ближе к Obsidian. Решение примем по прототипу Ф0.

## 7. Архитектура (без выбора технологий)

Слои: **оболочка** (окна, вкладки, настройки, локализация, горячие клавиши) → **редакторы** (общий холст, общий редактор текста, карточный и табличный вид) → **прикладной слой** (шина команд с undo, ссылки и обратные ссылки, поиск, вычислитель выражений, прохождение, проверки, экспорт) → **доменная модель** → **хранилище** (папка проекта, атомарная запись, копии, миграции; фоновые задачи вне потока интерфейса).

Ограничения:
- Цель **только Windows**: оболочка может опираться на возможности Windows (корзина, проводник, перетаскивание из ОС), но слои ниже оболочки остаются переносимыми, чтобы порты были возможны позже.
- **Open-source, потом Steam:** лицензия проекта **MIT**; все зависимости тоже с разрешительными лицензиями (MIT, BSD, Apache и подобные).
- **Лёгкий визуальный стиль:** отрисовка без размытий и теней в реальном времени; это заодно упрощает NFR-03.

ADR для этапа архитектуры: оболочка Windows-приложения; отрисовка холста; движок текста; язык выражений; генерация PDF; файл на объект или файл на модуль; лицензия.

## 8. Критерии приёмки ключевых функций

**Хранение:** 200 принудительных завершений во время записи → проект открывается 200 из 200, потеря ≤ интервала автосохранения. Копии в `backups/` создаются по расписанию; при политике «50» хранится не больше 50, при «бесконечно» ничего не удаляется. Удаление или порча `data/` не затрагивает `backups/`. Экспорт → импорт на другом ПК даёт идентичный проект (сравнение по хешам).

**Отмена:** 100 случайных операций → 100 отмен → 100 повторов в каждом редакторе: состояние совпадает. Ctrl+Z в тексте никогда не возвращает отменённое само.

**Текст:** вставка из Word, браузера и простого текста; ввод работает после Ctrl+V; контекстное меню в любом поле; панель форматирования отражает состояние сразу.

**Холст:** 5 000 узлов → ≥ 50 кадров/с; 500 реплик в одном диалоге; мини-карта синхронна с видом; плашка горячих клавиш одинаковая во всех графах; копирование 100 узлов из одного графа в другой сохраняет связи между ними.

**Логика:** выражение с несуществующей переменной подсвечивается при вводе. «Где используется» для переменной показывает все записи и чтения. Прохождение тестового сценария (50 узлов, 10 переменных, 5 выборов) воспроизводит эталонную последовательность. Ручное изменение переменной в прохождении меняет доступные варианты.

**БД:** изменение набора свойств отражается во всех сущностях без потери значений. Взаимная связь появляется у обеих сторон и удаляется у обеих. Ctrl+клик по ссылке открывает именно эту сущность. Изображение принимается из проводника, ресурсов и буфера. Ручной порядок сохраняется.

**Поиск:** «ser» находит «Sera» (имя) и «Whispering Forest… Sera…» (описание), имя выше; ≤ 100 мс; выпадающий список обновляется при каждом символе.

**Ресурсы:** перетаскивание папки с 3 уровнями вложенности и 200 файлами переносит структуру целиком; 90 и более изображений разом без потерь.

**Документы:** живая вставка обновляется ≤ 1 с после изменения сущности; PDF с кириллицей, без лишних разрывов; Markdown открывается в Obsidian (заголовки, списки, таблицы, изображения по относительным путям).

**Интерфейс:** все элементы доступны при 1366×768 / 100 % и 1920×1080 / 150 %; язык сохраняется; в RU-интерфейсе нет английских строк, кроме имён собственных (автоматическая проверка).
