## Как мы работаем

```
 ┌─ план фазы (короткий список задач в порядке выполнения) ─┐
 │                                                          │
 ▼                                                          │
 задача: код + автотесты + строки RU/EN + обновление плана   │
 ▼                                                          │
 CI на GitHub: тесты, бенчмарки, сборка Windows-установщика │
 ▼                                                          │
 веха: вы ставите установщик, проходите чек-лист вехи       │
 ▼                                                          │
 замечания (в чат или GitHub Issues) → исправления ─────────┘
```

- Я работаю в облачном Linux-контейнере: пишу код, гоняю автотесты, а Windows-установщик собирает CI на GitHub. **Интерфейс на Windows проверяете вы**; на каждой вехе есть ваша задача с чек-листом.
- Работа идёт в отдельных ветках и попадает в `main` после зелёного CI. Установщик собирается на каждую веху (тег версии) и выкладывается в GitHub Releases.
- **Публикация релиза** — человеком, потому что сессия Claude не может пушить теги. Проще всего так: GitHub → Releases → Draft a new release → тег вида `v0.1.0` → Publish. Через 15–20 минут CI сам прикрепит к релизу `HErPlan-<версия>-setup.exe`. Архивы «Source code» GitHub добавляет всегда, для установки они не нужны.
- **Номера версий** — `MAJOR.MINOR.PATCH`, каждый номер выходит один раз. Веха поднимает MINOR (`0.2.0` — «Сценарий»), исправления после неё — PATCH (`0.2.1`, `0.2.2`). Номер записан в пяти файлах; CI проверяет, что они совпадают, а тег релиза равен `v` + номер, иначе сборка релиза останавливается с объяснением. Сборки между релизами (артефакты Actions) несут номер прогона: `HErPlan-0.2.0-build57-setup.exe`, в «О программе» — «сборка 57».
- **Без подписи установщика** Windows покажет «Windows защитил ваш компьютер». Это ожидаемо: «Подробнее → Выполнить в любом случае». Подпись — в бэклоге (Ф9).

### Общий критерий «готово» для любой задачи

1. Автотесты на новую логику написаны и проходят в CI.
2. Все новые строки интерфейса есть на RU и EN.
3. Новые операции отменяются и повторяются (undo/redo).
4. Бенчмарк холста и время открытия эталонного проекта не ухудшились.
5. Документация (README, схема JSON, этот план) обновлена, если задача её касается.
